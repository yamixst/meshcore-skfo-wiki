# Инструкция по прошивке оборудования (MeshCore / Meshtastic)

В данном руководстве собраны методы прошивки микроконтроллеров ESP32 и nRF52840, ссылки на рекомендуемые веб-прошивальщики, инструкции по восстановлению загрузчика OTAFIX и оптимизации энергопотребления чипов.

---

## 1. Веб-прошивальщики (Web Serial API)

Самый быстрый и надежный способ прошивки оборудования без установки сложного инструментария разработки — использование веб-прошивальщиков. Для работы требуется браузер на движке Chromium (Google Chrome, Microsoft Edge, Яндекс.Браузер, Brave) с поддержкой **Web Serial API**.

```text
[ Плата через USB ] <---(Web Serial API)---> [ Браузер Chrome / Edge ] <---> [ Каталог прошивок ]
```

### Рекомендуемые ресурсы:
1. **[skmesh.ru/ru/flasher](https://skmesh.ru/ru/flasher)** / **[meshcoretel.ru/ru/flasher](https://meshcoretel.ru/ru/flasher)**:
   - Локализованный региональный прошивальщик сообщества СКФО.
   - Содержит актуальные стабильные билды MeshCore, настроенные под региональную частоту **868.900 МГц**.
   - Включает сборки наблюдателей VBart Observer.
2. **[flasher.meshcore.co.uk](https://flasher.meshcore.co.uk)**:
   - Официальный глобальный веб-прошивальщик проекта MeshCore.
3. **[mrekin.duckdns.org/flasher](https://mrekin.duckdns.org/flasher)**:
   - Каталог кастомных сборок от российского разработчика `@mrekin`.
   - Оптимизированные и облегченные версии для платформ nRF52 и ESP32.
4. **[flasher.meshtastic.org](https://flasher.meshtastic.org)**:
   - Официальный прошивальщик для протокола Meshtastic (если требуется вернуться на стоковую прошивку).

## 2. Специфика nRF52840 и загрузчик «OTAFIX Bootloader»

Платы на базе чипсета **Nordic nRF52840** (Heltec T114, Seeed Xiao nRF52840, SuperMini / ProMicro nRF52840, Ebyte E73) являются золотым стандартом автономности, потребляя в десятки раз меньше энергии, чем ESP32. Однако при частых обновлениях по USB или OTA многие пользователи сталкивались с критической проблемой зависания штатного загрузчика Adafruit nRF52 Bootloader в циклическом режиме DFU.

### Решение: OTAFIX Bootloader (v0.9.2-OTAFIX2.1 / OTAFIX2.2)
Разработчиками подготовлено исправленное ядро вторичного загрузчика, исключающее зацикливание DFU-режима и сбои адресации флеш-памяти.

#### Файлы обновления:
- Для Heltec T114: `update-t114_bootloader-0.9.2-OTAFIX2.1.uf2`
- Для ProMicro / SuperMini nRF52840: `promicro_nrf52840_bootloader-0.9.2-OTAFIX2.2.uf2`

#### Пошаговая инструкция по обновлению загрузчика:
1. Подключите плату к компьютеру по качественному USB-C кабелю.
2. Быстро дважды нажмите кнопку **RESET** (двойной клик с интервалом менее 0.5 с). Плата определится в операционной системе как съемный USB-накопитель (например, `NRF52BOOT` или `T114BOOT`).
3. Скопируйте соответствующий файл `.uf2` в корень появившегося накопителя.
4. Плата автоматически перезагрузится за несколько секунд.
5. **Проверка успешности:** Снова сделайте двойной клик Reset, откройте файл `INFO_UF2.TXT` на накопителе. Первая строка должна содержать подтверждение: `UF2 Bootloader 0.9.2-OTAFIX...`.
6. После этого скопируйте бинарник самой прошивки MeshCore (`firmware.uf2`) в корень диска.

## 3. Прошивка через утилиты командной строки (CLI)

Для автоматизации или глубокого восстановления «окирпиченных» плат используются стандартные низкоуровневые утилиты.

### 3.1. Для плат на базе ESP32 (Heltec V3/V4, T-Beam, LilyGO) — `esptool.py`
Установка утилиты:
```bash
pip install esptool
```

Полное стирание памяти (рекомендуется при смене протокола Meshtastic <-> MeshCore):
```bash
esptool.py --port /dev/ttyUSB0 erase_flash
```

Заливка прошивки MeshCore:
```bash
esptool.py --port /dev/ttyUSB0 --baud 921600 write_flash 0x0 meshcore_firmware.bin
```

### 3.2. Для плат nRF52840 через программатор J-Link / DAPLink — `nrfutil`
Если загрузчик поврежден полностью и плата не входит в UF2 по двойному клику:
```bash
# Восстановление через Segger J-Link / nrfjprog
nrfjprog -f nrf52 --recover
nrfjprog -f nrf52 --program bootloader.hex --chiperase --verify
nrfjprog -f nrf52 --reset
```

## 4. Энергосберегающие сборки и понижение частоты ядра (40 МГц)

В стационарных ретрансляторах и диких автономных нодах на чипах ESP32 главной проблемой является высокое токопотребление кристалла (до 80–120 мА даже в простое).

### Механизмы экономии кастомных прошивок (VBart Eco / Astroed Mod):
1. **Понижение тактовой частоты CPU:**
   - Штатная частота ESP32 составляет **240 МГц**. Для обработки медленных пакетов LoRa со скоростью 1–2 кбит/с такая производительность избыточна.
   - В модифицированных прошивках частота процессора принудительно снижена до **40–80 МГц**.
   - Понижение частоты до 40 МГц снижает базовый аппетит чипа более чем в 3 раза без потери стабильности вычислений.
2. **Оптимизация периферии:**
   - Полное отключение интерфейсов Wi-Fi и Bluetooth в режиме репитера.
   - Отключение неиспользуемых источников пробуждения (Wakeup triggers): таймеры, лишние пины GPIO, сопроцессор ULP.
   - Перевод ядра в режим глубокого сна `Light Sleep` в интервалах между CAD-проверками эфира.
3. **Результат:** Автономность ESP32-ноды на одной ячейке 18650 вырастает с 12–15 часов до почти 3 суток.
