# Интеграция MQTT, Наблюдатели (Observers) и сервисы мониторинга

Интеграция ячеистой радиосети с IP-сетями через брокеры MQTT позволяет объединять территориально удаленные сегменты, выводить узлы на интерактивные карты покрытия и собирать детальную диагностическую телеметрию. Однако радиоканал LoRa имеет крайне ограниченную пропускную способность, поэтому подключение к интернету регламентируется строгими правилами.

---

## 1. Федеральный брокер OneMesh и супертопик `msh/RU/STV`

Сообщество Ставропольского края и СКФО интегрировано в общероссийскую экосистему мониторинга **OneMesh** ([onemesh.ru](https://onemesh.ru)):

### Реквизиты подключения:
- **Сервер (Broker Host):** `mqtt.onemesh.ru`
- **Порт:** `1883` (TCP без TLS) или `8883` (SSL/TLS)
- **Имя пользователя (Username):** `onemesh`
- **Пароль (Password):** `onemesh`
- **Корневой топик региона:** `msh/RU/STV`

### Структура регионального супертопика:
По согласованию с архитектором OneMesh, топик `msh/RU/STV` сконфигурирован как агрегирующий супертопик, объединяющий три ключевых агломерационных кластера Ставропольского края:
1. `STV` — г. Ставрополь и Михайловск;
2. `NEV` — г. Невинномысск и прилегающие промышленные зоны;
3. `KMV` — Кавказские Минеральные Воды (Пятигорск, Кисловодск, Ессентуки, Минеральные Воды).

## 2. Жесткое правило эфирной гигиены: Запрет Downlink

> [!CAUTION]
> **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО включать опцию DOWNLINK на любых MQTT-шлюзах сети!**
> Разрешен исключительно режим **UPLINK ONLY**.

### Почему Downlink смертелен для LoRa-сети:
- **Суть проблемы:** Если хотя бы один шлюз активирует Downlink, любой пакет, отправленный через интернет-интерфейс в топик брокера (например, ботом из Москвы или спам-скриптом), немедленно выплескивается через радиомодем шлюза в радиоэфир Ставрополя на частоте 868.900 МГц.
- **Эфирный паралич:** Интернет-канал имеет пропускную способность сотни мегабит, а радиоканал LoRa BW 62.5 кГц — единицы килобит. Включение Downlink мгновенно забивает эфир на 100%, парализует репитеры и блокирует реальные радиопереговоры местных пользователей.
- **Регламент:** Шлюзы обязаны работать в режиме пассивного радиомониторинга: ловить пакеты из радиоэфира и передавать их **вверх (Uplink)** на сервер карты. Обратный вброс пакетов из сети в эфир запрещен.

```text
[ Радиоэфир СКФО ] ----(Пакеты из эфира)----> [ Наблюдатель / Шлюз ] ----(Uplink)----> [ MQTT: mqtt.onemesh.ru ]
                                                                                                |
[ Радиоэфир СКФО ] <=== БЛОКИРОВКА (НЕТ) === [ Наблюдатель / Шлюз ] <---(Downlink ЗАПРЕЩЕН)----+
```

## 3. Региональный сервис SkMesh.ru

Для решения сугубо региональных задач телеметрии сообществом развернут собственный сервис **[SkMesh.ru](https://skmesh.ru)**:
- **Назначение:** Мониторинг здоровья и напряжения аккумуляторов автономных репитеров на высотах, отображение тепловой карты покрытия и аналитика треков вардрайвинга.
- **Локальный брокер телеметрии:** `skmesh.ru` (порт 1883).
- **Интеграция:** Поддержка персонализированных токенов для мобильных клиентов MCOa и прошивок VBart.

## 4. Прошивка «VBart Observer» (MeshCoreTel)

Специально для стационарных наблюдателей и интернет-шлюзов разработчиками сообщества (*DenSSS*, *Astroed*) была адаптирована кастомная прошивка **VBart Observer**:

### Архитектурные особенности:
1. **Асимметричная нагрузка на ядра (Dual Core):**
   - **Ядро 0 (Core 0):** Реальное время радиомодема LoRa (прием пакетов, детекция преамбулы, фильтрация). Радиоинтерфейс никогда не испытывает задержек.
   - **Ядро 1 (Core 1):** Стек сетевых протоколов (Wi-Fi, HTTPS веб-сервер, REST API, MQTT-клиент).
2. **Встроенный веб-интерфейс:**
   - Доступ по локальному IP-адресу через любой браузер.
   - Отображение текущего RSSI/SNR эфира в реальном времени.
   - Консоль для выполнения команд CLI без подключения по USB-кабелю.
   - Возможность беспроводного обновления бинарников прошивки прямо из браузера.
3. **Энергоэффективность:**
   - На платах ESP32 без оптимизации Wi-Fi сажает стандартный аккумулятор 18650 емкостью 3000 мАч за 8–12 часов.
   - В энергосберегающей сборке VBart Observer с агрессивным режимом `WIFI_PS_MIN_MODEM` узел живет **до 2 суток 22 часов** от одной ячейки 18650, периодически просыпаясь для передачи накопленных пачек телеметрии.

### Пример базовой настройки CLI в VBart Observer:
```text
set wifi.ssid "MyHomeWiFi"
set wifi.password "MySecretPass"
set mqtt.server "skmesh.ru"
set mqtt.port 1883
set mqtt.topic "msh/RU/STV"
set mqtt.downlink off        # Жесткое отключение нисходящего интернет-трафика
reboot
```
